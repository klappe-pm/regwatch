# explanation

Explanation pages give background and reasons for the code. They are for reading away from the keyboard, when you want to understand why regwatch is built as it is before you change it. They discuss tradeoffs and alternatives, which the tutorials, how-to guides and reference pages leave out on purpose.

## pages

- [architecture](architecture.md): how the modules fit together, which way data flows, and where the trust boundaries sit.
- [design decisions](design-decisions.md): the choices that shaped the code, with the alternative each one rejected, including what was deliberately not built.
