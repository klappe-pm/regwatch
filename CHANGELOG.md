# Changelog

All notable changes to this project are documented in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Unreleased

### Added

- Generated copy, a premium feature that is off by default: a language model writes the opening and short summaries of a newsletter or a document from structured facts with ids, and every passage that cites a fact it was not given is dropped and reported. Kept passages are labelled Generated in Markdown, HTML, plain text and Word, shown next to the facts they cite, and escaped like every other value. Anthropic is the default provider, with OpenAI and a local Ollama model by setting. `regwatch llm status`, `on`, `off` and `use PROVIDER [--model NAME]` change the new `[llm]` table, and `regwatch keys set llm-anthropic` or `llm-openai` keeps the provider key in the keychain under a fixed name. Each call adds one line to `llm-calls.jsonl` in the state directory with the provider, the model, the token counts and the duration, never the prompt or the key. [turn on generated copy](docs/how-to-guides/turn-on-generated-copy.md) walks through it.
- A POST in the fetch client, `post_json`, with the same address checks, size limit and deadline as a GET, no redirects, and plain http only to a loopback IP literal with `allow_private_hosts` set and never with a key.
- The document model gains generated passages: each section may hold passages with the ids they cite, the facts behind them and the provider and model that wrote them.
- A source catalogue in package data, `regwatch/data/source-catalogue.json`: 575 sources worldwide, each with its jurisdiction, region, kind, category, mechanism, address and whether it is Free, needs a free key or is Paid, checked on 2026-10-23. Loading validates every field strictly, and a catalogue of your own named in the new `[catalogue] extra` setting follows the same rules. [source catalogue](docs/reference/source-catalogue.md) describes it.
- `regwatch sources` with `list` (filters by region, jurisdiction, kind, category, access, focus area and your chosen sources), `search` (one ranking for every surface), `show`, `add` (copies entries into your sources file and adds missing jurisdictions, never overwriting a different entry), `remove` and `verify`, and `--json` output for `list`, `search` and `show`.
- Optional `auth` and `key_env` fields in the sources file for sources that need a key.
- `regwatch keys set`, `list` and `remove`: keys for keyed sources kept in the macOS login keychain or the Linux Secret Service, with an environment variable override, never on a command line and never printed.
- Keyed fetches: a key is sent only over `https`, only to its own source's host and port, in the query parameter or header the source names, is dropped on a redirect to another host, and is removed from every error message.
- `regwatch run`, which captures and checks every source and writes a run record (the newest 500 are kept), and `regwatch schedule` with `--install`, `--show`, `--remove`, `--every` and `--dry-run`, which installs it as a launchd agent on macOS or a crontab block elsewhere.
- `python -m regwatch`, which a schedule uses.
- Guided setup in `regwatch init`: after focus areas and jurisdictions it lists the matching catalogue sources grouped by category and region, with search as you type (Tab completion on a terminal, a numbered list otherwise), select and unselect, and a source of your own; then walks through keys for chosen keyed sources, offers a schedule and offers a first run. `--sources`, `--schedule`, `--no-schedule`, `--first-run` and `--no-first-run` script every step, and `--yes` still writes the same files as before when no source is chosen.
- Package scaffold: `pyproject.toml` with the hatchling build backend and the `regwatch` console script. There are no runtime dependencies.
- The `regwatch` command with the subcommands `validate`, `coverage`, `list`, `portfolio`, `capture`, `check`, `ingest`, `impact`, `themes`, `brief`, `render`, `digest`, `report` and `export`, and later `init` and `config`. [cli reference](docs/reference/cli.md) documents each.
- A TOML configuration file that names the register files, the state directory, the fetch limits and the ingest filters. [configuration](docs/reference/configuration.md) lists every key.
- The register data model: obligations as CSV, and jurisdictions, categories, sources and a portfolio as JSON, with optional detail, change log, enforcement and theme files. Field rules ship as package data in `regwatch/data/schema.json`. [data files](docs/reference/data-files.md) describes each file.
- Change detection by content hash for `api`, `rss`, `html`, `email-list` and `manual` sources, with snapshots for repeatable offline checks and an explicit `--accept` step that records the baseline.
- One fetch client that allows only `https` and `file` URLs, refuses hosts that resolve to loopback, link-local, private or other non-public addresses and connects to the address it vetted, follows at most 5 redirects and only to `https`, always verifies certificates, enforces a per-operation timeout, a total deadline and a size limit, ignores proxy variables, reads `file` sources only from regular files under `allowed_file_roots`, and never starts a program.
- Cleaning of untrusted text: control and escape characters removed, links validated, Markdown output escaped, and CSV formula cells neutralised.
- Change detection that cannot be hidden: a `SUSPICIOUS` status for an empty or sharply shorter source, an `--accept-suspicious` flag, and exit status 4 from `check --exit-code` for a source in `ERROR` or `MISSING`.
- Write protection by file identity, covering `regwatch.toml` and the state files as well as the register.
- Defensive parsing of fetched content: JSON through `json`, HTML through the standard library tokenizer, and feeds through ElementTree after any DTD or entity declaration is refused.
- Candidate ingest from a Federal Register style API response, flagged unconfirmed.
- Candidate impact analysis that joins obligations to products by jurisdiction exposure, scope and shared categories, terms or claims, with severity scoring and optional themes.
- Daily, weekly and tiered briefings built as one document model, and renderers for Markdown, a web post, an HTML and plain text newsletter, and a Word document. Every output carries the disclaimer that nothing is legal advice.
- A synthetic example register, snapshots and ingest response under `examples/`.
- Documentation in one tree under `docs/`, arranged by Diátaxis quadrant, for people who use regwatch and for people who change it.
- A test suite that blocks the network and checks the documentation and the repository, with a coverage report.
- `regwatch init`, a configuration flow that scaffolds a project: `regwatch.toml`, an empty register that validates, and an editable copy of the focus catalogue. It asks on the terminal with plain prompts and no new dependency, every question has a flag, `--yes` takes the defaults so it can be scripted, and `--example` offers the invented example jurisdictions. It asks for the project folder (never assuming the home directory), focus areas and custom terms, jurisdictions, whether local file sources are allowed and from which folders (default none), and a User-Agent contact. It shows a summary and asks before writing, refuses to overwrite existing files without `--force`, never writes through a symbolic link, and refuses a file root that is a file system root or the home directory. [cli reference](docs/reference/cli.md) documents it.
- A shipped, editable focus catalogue in package data with eight areas: non-alcoholic beverages, alcoholic beverages, cannabis and hemp products, traditional foods, dietary supplements, infant food, pet food and cosmetics. [focus catalogue](docs/reference/focus-catalogue.md) describes the format and the matching rules.
- A `[profile]` table in `regwatch.toml` that records the chosen focus areas, custom terms and an optional catalogue path. Impact analysis, the tiered briefing and the daily and weekly briefs rank candidates that match a focus area first, and list the rest under an outside-your-focus-areas heading. Nothing is dropped.
- `regwatch config show`, which prints the effective configuration, including focus areas, the catalogue in use and the allowed file roots.
- A how-to guide, [set your focus areas](docs/how-to-guides/set-your-focus-areas.md), and a getting started tutorial that begins with `regwatch init`.
- `regwatch ui`, a local web app in the browser over the same files as the command line: Overview, Changes, Sources, Obligations, Briefings, Newsletters, Documents, Automations, Keys and Settings, a collapsible navigation rail and one search over sources, changes and obligations. The pages are a static export of a Next.js and Tailwind CSS app, shipped inside the package under `regwatch/web/`, so no Node is needed to run them, and they load nothing from another origin. [use the web app](docs/how-to-guides/use-the-web-app.md) describes it.
- A local server for `regwatch ui` on the standard library's `ThreadingHTTPServer`, bound to `127.0.0.1` only. Every request needs a random token that moves from the opened address into an `HttpOnly`, `SameSite=Strict` cookie; a request for another host name, a change from another origin or a change that is not JSON is refused; files are served only from inside the build folder after links are resolved; and every response carries a content security policy that names no other origin. [security model](docs/explanation/security-model.md#the-local-server) explains each check.
- A JSON interface behind the web app, in `regwatch/webapi.py`, with no route that returns a key. It does what the commands do through the same functions, now shared in `regwatch/workspace.py`: the Sources page searches the catalogue with the `sources search` ranking, groups and filters it by category, region, kind and access, and adds a source as `sources add` does; the Keys page shows where each key comes from and sets and removes keys as `regwatch keys` does; the Automations page shows the installed schedule with its next run and the run records, and Run now runs `regwatch run` in a background thread, one run at a time; the Overview shows the next run and a Supply Chain section listing your ingredients, packaging and commodities sources with their last status.
- `regwatch premium on`, `off` and `status`, and a `[premium] enabled` setting, default off, read by the configuration loader and shown by `config show`. Premium features (newsletters, document templates, generated copy and runs more often than once a day) are shown with a lock while it is off.
- Settings changes from `regwatch premium` and the web app's Settings page edit one line of `regwatch.toml`, keep every comment and every other setting, and leave a file they cannot change safely untouched.
- `scripts/build-web.sh`, which builds the web app from its lockfile reproducibly, and a release workflow step that rebuilds it with `npm ci` and fails when the committed copy differs. [change the web app](docs/how-to-guides/change-the-web-app.md) describes the steps.
- Community files: a code of conduct, issue templates for a bug report, a feature request and a question, a pull request template, and a README banner drawn by `scripts/make-banner.py`.
- Package metadata for PyPI: keywords, classifiers, project URLs, a `test` extra (`pytest` 9.0.3 or newer and `pytest-cov`) and a `lint` extra (`ruff` and `mypy`).
- A release workflow in three jobs. `build` checks that the tag is on `main` and equals the package version, builds with a hash-pinned `hatchling` and writes the checksums to the job summary. `test` installs the built wheel and runs the suite against it. `publish` uploads through trusted publishing and needs both. The lock files are in `requirements/`. [cut a release](docs/how-to-guides/cut-a-release.md) describes the one-time PyPI and GitHub setup.

### Security

- CSV export: every field is quoted, and a part of a cell that would run as a formula is neutralised after a `;`, a `,`, a tab or a line break, after leading whitespace or invisible format characters, and in the fullwidth forms, so a spreadsheet that splits on semicolons cannot be made to run a formula.
- Terminal output: every line regwatch prints goes through one function that removes control characters and invisible format characters, `FetchError` cleans its own message (a server controls part of it), and `regwatch validate` refuses control characters in register text. A hostile status line, register value or catalogue label can no longer clear the screen, set a window title or add a line.
- Text cleaning removes bidirectional overrides and isolates and zero-width characters, and a link whose host is not plain ASCII, or that holds an invisible format character, is refused.
- Fetch client: IPv6 forms that embed an IPv4 address (NAT64, 6to4, Teredo, ISATAP) are judged by the embedded address, all of `::/8` (IPv4-compatible and SIIT forms included), site-local `fec0::/10` and the NAT64 prefix `64:ff9b::/32` outside its `/96` are refused, an IPv6 literal host is bracketed in the Host header, the total deadline now covers the name lookup, and a local file swapped for a link or another file between the root check and the open is refused.
- Markdown output: text that a renderer would link on its own is kept as text, and a value made only of hyphens or equals signs can no longer draw a horizontal rule. A word with an `@` or a `scheme:` prefix (an email address, `mailto:`, `xmpp:`, a web address) is written in a code span whose fence is longer than any backtick run inside it, the dot after `www` and every dot between two word characters in any script are escaped, and the colon of `://` is escaped. Rendering the test values with cmark-gfm (the renderer GitHub uses, through the `cmarkgfm` package, now in `requirements/ci.in` and `ci.txt` with hashes) and with markdown-it with linkify produces no link. That is what is guaranteed; other renderers are not tested. A web address in a briefing is shown as text.
- Output paths: a path that is itself a symbolic link is refused, an existing file keeps its permission bits, and a new file gets the permissions the umask allows instead of 0600.
- `regwatch init` looks again right before it writes and creates each file exclusively, so a file or link that appears while it asks is never replaced or followed. It also opens the project folder and `register/` without following a link before it writes anything and creates every file through those open folders (a replacement with `--force` is a temporary file renamed in the same folder), so a folder swapped for a link at the last moment cannot redirect a write.
- A candidates file that is deeply nested or larger than 20,000,000 bytes is a clean error from `brief` instead of a crash.
- Configuration: a hand-written `allowed_file_roots` entry of `/`, the home directory or any parent of the home directory is refused, as it already was in `regwatch init`, which now refuses a parent of the home directory too.
- Key variables: a source's `key_env` must match `REGWATCH_KEY_` followed by 1 to 51 upper case letters, digits and underscores, in the catalogue, an extra catalogue file, the sources file and at fetch time, so a source can no longer name an unrelated environment variable (a cloud credential or a deploy token) and have its value sent. Two sources that name the same key variable must send it to the same host and port; the catalogue and the sources file refuse a variable shared across hosts.
- `regwatch ui`: the token in the address is single use. The first browser that opens it gets a separate random session cookie and the token is spent, so the printed address, the terminal scrollback and the copy in the browser's command line (readable by every local user on Linux) no longer grant access once the browser has opened it. A second use is refused with a message that says to restart the server.
- Keyed fetches: a response body that echoes the key (as raw text, percent-encoded, HTML-escaped or JSON-escaped) has it replaced with `[key]` before it is returned, so it is never stored in a snapshot. An error message has the key removed before it is cleaned and cut to 1,000 characters and again after cleaning, so a key cut at the limit or split by an invisible character no longer leaves a fragment.
- `regwatch keys set` on macOS refuses a key that would make the line written to `security -i` longer than 4,095 bytes, which `security` would split at its 4,096 byte buffer and read the tail as a second command. The message says how long the key may be for that key name and names the environment variable to use instead.
- `regwatch ui`: a connection that makes no progress for 30 seconds is closed, and at most 32 connections are handled at once, so another local program holding idle connections open can no longer exhaust the server's threads.
- The web app is built with `next` 15.5.28, which fixes GHSA-2464-fhr4-w9xw and GHSA-p3m5-59mp-jv5r, and `next`'s own copy of `postcss` is pinned to 8.5.29 through `overrides`, which fixes GHSA-qx2v-qp2m-jg93, GHSA-6g55-p6wh-862q, GHSA-fxqj-rqcc-2cmp and GHSA-r28c-9q8g-f849. `npm audit --package-lock-only` reports no vulnerabilities, and the build is still reproducible from the lockfile. The pages are a static export served by Regwatch's own server, so neither the image optimisation API nor server actions were reachable, but the lockfile no longer carries the vulnerable versions.

### Fixed

- Docs and copy: the `ui` reference no longer says the web app fetches nothing (Run now does what `regwatch run` does), the source catalogue reference no longer calls the web app's catalogue search planned, `keys set`, `keys list` and `keys remove` have help descriptions, and the "Why It Was Flagged" and "Impacts on Your Products" headings are Title Case.
- `regwatch sources list --jurisdiction` matches in any case, so `US` lists the same sources as `us`, and an unknown `--focus` exits 2 naming the valid focus area ids instead of listing only the entries that serve every area.
- `regwatch sources verify` sends the stored key for a keyed source and reports `no key`, with the `regwatch keys set` command, when there is none, instead of fetching without it. With no ids it verifies the catalogue entries of your sources file; `--all` verifies the whole catalogue. A missing key also makes the exit status 4.
- The global search in the web app showed No matches when the request failed; it now shows the error. A catalogue hit opens the catalogue search by its id, not its name, so it finds that one source.
- The Documents and Newsletters pages showed Loading forever when the status request failed, because the error was dropped. The shared status now carries the error, and both pages show it in an error note.
- Run records written in the same second sorted by their random suffix, so the activity view could show them out of order and pruning could remove the record just written. A run record name now carries the start time to the microsecond and a four digit sequence for records with the same start, the records sort by start time and then sequence, and the newest is never pruned. Records named in the earlier form are still read.
- A schedule installed before any run never ran: the crontab line and the launchd agent send the output to `schedule.log` in the state directory, which neither cron nor launchd creates, and nothing had created it yet. `regwatch schedule --install`, and so `regwatch init --schedule`, now creates the state directory first, and refuses a state path that is a file or a dangling link.
- Catalogue search ranked poorly: `fda` put Taiwan's and Thailand's regulators and trade press among the FDA's own sources, `aluminium` and `aluminum` found different sources, `ca` matched every word containing "ca", and the access label and focus areas were not searched. The one ranking (the CLI, `init` and the web app) now weights the fields (name 4, id and publisher 3, jurisdiction, kind and access label 2, region, category, focus areas and description 1), matches a publisher by its initials, treats British and American spellings alike in both directions, matches a one or two letter word only as a whole word or id part, and puts official sources first among equals. A whole word still always beats the start of a word.
- Hourly runs were shown as a premium feature but installed without it. With premium off, `regwatch schedule --every hourly` now exits 2 with a message naming `regwatch premium on`, and a default cadence of hourly (from a source's cadence) is capped at daily with a note.
- The Sources page of the web app regrouped search results by category, so the best match was buried under whichever category came first. While a search is typed the catalogue is now one list in the ranking's order, best match first, with each source's category beside its publisher; it is grouped by category only when the search box is empty. The layout rule is a plain module with tests run by Node's built-in test runner (`npm --prefix web test`), which the Python suite also runs when Node 22.18 or newer is present.
- `regwatch init --schedule` on a machine without `crontab` or `launchctl` stopped with an error after writing the files, skipping the first run and the closing guidance. It now prints the error and the command to install the schedule later, then carries on; the exit status is 2 when nothing else is to report.
- Source catalogue corrections. `us-ecfr-title-21` watched a dated 2.7 MB snapshot that was over the fetch limit and could never change; it now watches the 270 KB list of Title 21 amendments. `us-fda-food-facility-registration` is filed under regulation, `intl-mintel` under industry news, and `us-legiscan-api` under regulation as a manual source, because its API could not be confirmed without a key. `jp-egov-law-api`, `eu-publications-office-sparql`, `us-census-api-catalog` and `intl-wto-api-portal` named documentation or catalogue pages as `api` sources and are now watched as `html`; the census and WTO pages need no key, so they no longer send one, and the census address moved to the 390 KB developer page because the machine catalog is over the fetch limit. `intl-eping-wto` is manual, since no public API is confirmed. `ca-health-canada-news-atom` is read as `rss` and names the department `departmentofhealth`, as the old value returned an empty feed. `ca-bc-liquor-cannabis-lcrb` points at the Liquor and Cannabis Regulation Branch on gov.bc.ca instead of the government liquor store, `us-md-food-regulator` at the Office of Food Protection instead of the department home page, and `us-fred-api` and `us-bls-public-api` at a concrete series, the producer price index for metal can manufacturing (PCU332431332431). A test checks that no `api` entry points at a page or a documentation path.
- Tab completion in `regwatch init` treated the whole answer as one word, so the second id in `nl-notices us-fda-rec` never completed, and it offered names whose spaces could not be completed or selected. It now splits on spaces and commas and completes ids, and a source's full name typed on its own selects that source.
- The security model now says plainly that only the last part of an output path is checked for being a symbolic link: a link planted in a folder above it is followed, Linux can limit that in sticky world-writable folders with `fs.protected_symlinks`, and macOS has no such setting.
- Fetching a source whose host is written in other scripts, or whose path or query holds non-ASCII characters, now works: the host goes on the wire in its `xn--` form for the lookup, the TLS server name and the Host header, the path and query are percent-encoded, and a host that cannot be encoded is a clear `FetchError`. Links shown to readers still require a plain ASCII host.
- A document model whose section `level` is a number with a fraction, such as `2.0`, is refused with a clean error from `render` instead of crashing the renderer. Only the integers 2, 3 and 4 are accepted.
- Escaping Markdown no longer takes time that grows with the square of a word's length. A 64,000 letter word took 5.2 seconds and a 40 paragraph render of 20,000 letter words took 19.7 seconds; both now take well under a tenth of a second, and a one mebibyte word takes about 0.08 seconds.
- A dot after a combining mark, a Devanagari or Tamil vowel sign, an emoji or a symbol is now escaped in Markdown output, so markdown-it with linkify no longer links a name such as an e with a combining accent before `.com`, a Hindi or Tamil name ending in a vowel sign, or `™.com`. Every dot followed by a non-space character is escaped, whatever precedes it.
- Fetching a host that Python's IDNA 2003 codec would silently map to a different name is refused with a `FetchError`: `faß.de` (which became `fass.de`), `straße.de`, a name with a zero-width joiner and a name with a soft hyphen are never resolved. The encoded name must decode back to the NFC, lower case name that was asked for, and the ideographic, fullwidth and halfwidth full stops count as dots.
- An IPv6 address that carries two embedded IPv4 addresses, such as a 6to4 prefix with an ISATAP interface identifier, is public only when both are. `2002:808:808::200:5efe:7f00:1` (public 6to4, loopback ISATAP) used to pass because only the first form was judged.
- An ISATAP address whose interface identifier has the group bit set (`100:5efe` and `300:5efe`, as in `2600::100:5efe:7f00:1`) is now judged by the IPv4 address it carries. Only `0:5efe` and `200:5efe` were recognised, so those two forms passed as public with a loopback, private or link-local address inside. A public IPv4 address inside any of the four forms stays public.
- The error for a file root that is too broad now says what is refused: "not a file system root, your home directory or a folder that contains it". It said "not a file system root or your home directory" even when the folder was a parent of the home directory such as `/home`.
- The tests that read the repository (`test_docs.py`, `test_docs_content.py`, `test_no_personal_terms.py` and `test_release_workflow.py`) imported `tests.conftest` and `tests.test_docs`, but `tests/` is not a package, so running them from the extracted source distribution against the installed wheel ended with `ModuleNotFoundError: No module named 'tests'`. They import `conftest` and `test_docs` by plain name, as the other test modules do, and a test checks that no test module imports `tests` as a package.
- A Markdown value that is only a list marker (`1.`, `9)`, `2027.` or `+`) is escaped like a marker followed by text, so it renders as a paragraph and no longer starts an empty ordered or bullet list.
