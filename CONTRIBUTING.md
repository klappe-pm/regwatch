# Contributing

Thank you for helping improve Regwatch. Open an issue to discuss a change before writing a large pull request, so the effort goes where it will be merged. This page holds the rules every contribution follows; the walkthroughs and reference live under [docs](docs/README.md), starting with [First Contribution](docs/tutorials/first-contribution.md). Everyone taking part is expected to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Setup

```bash
git clone https://github.com/klappe-pm/regwatch && cd regwatch && python3 -m venv .venv && . .venv/bin/activate && pip install -e '.[dev]'
```

## Tests

Run the suite before every commit. [Run the Tests](docs/how-to-guides/run-the-tests.md) covers coverage, lint, formatting and type checking, which a change must also pass.

```bash
python3 -m pytest
```

## Guidelines

- Python 3.11 or newer, standard library only at runtime. `pytest`, `pytest-cov`, `ruff` and `mypy` are development dependencies. A new runtime dependency needs a written justification in [Dependencies](docs/explanation/dependencies.md) and an issue agreed beforehand.
- Package data lives under `regwatch/data/` and is read through `importlib.resources`, never through a path built from `__file__`. See [Package Data](docs/reference/package-data.md).
- Tests read fixtures only: never the live home directory, a real network or a real register. The test suite blocks sockets, so a test that tries to reach the network fails.
- Examples and fixtures are synthetic. Never add a real register, a real company or client name, or data copied from a private source.
- Network access goes through the one fetch client in `regwatch/fetch.py`. Do not call `urllib`, `socket` or a subprocess from anywhere else.
- Text from outside goes through `regwatch/sanitize.py` before it is stored, printed or rendered. A link is accepted only through `safe_https_url`.
- Fetched content is untrusted. Parse it with the functions in `regwatch/extract.py` and never with `eval`, `pickle` or an XML parser that resolves entities.
- Regwatch never writes to a register file. Every write goes through `regwatch/state.py`.
- Documentation goes in `docs/`, in the folder for its kind: `tutorials/`, `how-to-guides/`, `reference/` or `explanation/`. Filenames are lowercase kebab-case, apart from `README.md`, `LICENSE` and the uppercase community files. Headings use Title Case, and each paragraph and list item is one line, not hard-wrapped. Do not use dashes as punctuation.
- The README banner is generated by `scripts/make-banner.py`, which needs `fonttools` and the DejaVu Sans Mono fonts. `fonttools` is only for that script and is not a dependency of the package.
- Keep any list of private terms to check for (client names, project names) in a file outside the repository, and point `REGWATCH_FORBIDDEN_TERMS_FILE` at it when you run the tests. Never write such terms in the repository.
- Never commit a secret, credential, private key or `.env` file. `.env.example` with placeholder values is allowed.
- Everything committed here is visible to anyone. Never add `models`, `providers` or `session-link` keys to the frontmatter of any Markdown file, and never add a session link anywhere.
- Never credit an agent, assistant, model, model provider or agent runtime as author or contributor in files, commits, pull requests or comments. No co-author trailers and no "generated with" lines.
- Agent instruction files and runtime directories at the repository root (`AGENTS.md`, `CLAUDE.md`, `CODEX.md`, `GEMINI.md`, `.claude/` and the like) are gitignored and never tracked.
- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/).

## Pull Requests

Keep each pull request to one change, describe what it does and how you tested it, and make sure the test suite, `ruff check`, `ruff format --check` and `mypy` pass. Add a line under Unreleased in [CHANGELOG.md](CHANGELOG.md) for any user-visible change.
